# mAP50 0.9718，为什么数株数还是差 15%

> `eval_report.md` 里有一组互相矛盾的数字，之前一直挂着没解：
>
> ```
> mAP50 0.9718   Recall 0.9515     → 检测看着很好
> 计数 MAE 7.57 个/图  MAPE 15.59%  → 计数很难看
> 完全数对 2.7%   误差≤3 仅 16.0%
> bias +7.52（预测 4329 vs 真实 3765，多 15%）
> ```
>
> 而且 **bias 几乎等于 MAE**（7.52 / 7.57），说明误差有 99% 来自**系统性多检**，
> 不是随机抖动。这篇记的是归因过程和结论。

## 1. 两个互斥的假设

| | 假设 | 若成立，证据应该长什么样 |
|---|---|---|
| A | **模型过检**：低置信框是误检 | 抬高 conf，bias 单调收敛到 0；多余框与 GT 无关 |
| B | **GT 漏标**：模型检对了但没被标 | 抬阈值后 bias 仍为正；多余框紧贴 GT（部分重叠） |

两者的处置完全不同：A 改阈值，B 要重标数据。所以必须先分开。

## 2. 做法

一次推理把 conf 压到 0.001 收全部候选（test 集 75 张共 11 299 个框），然后**只在
内存里扫阈值**，不重复推理。对每个阈值同时算：

- 计数侧：bias / MAE / MAPE / 完全数对率
- 检测侧：按 IoU≥0.5 贪心匹配出 TP / FP / FN（与 mAP50 同口径）
- 归因：每个没匹配上的框，量它到最近 GT 的**中心距 / 自身对角线**与 IoU

脚本 `scripts/bias_diagnose.py`，一条命令复现。

## 3. 三条证据都指向 A

**① bias 随阈值单调下降，并穿过零。**

| conf | 预测 | bias | MAE | 完全数对 | Recall |
|---|---|---|---|---|---|
| 0.05 | 4966 | +16.01 | 16.01 | 0.0% | 96.9% |
| 0.25 | 4183 | +5.57 | 5.71 | 9.3% | 96.8% |
| 0.40 | 3995 | +3.07 | 3.84 | 5.3% | 96.4% |
| 0.50 | 3867 | +1.36 | 2.83 | 16.0% | 95.8% |
| **0.55** | **3802** | **+0.49** | **2.55** | **14.7%** | **95.3%** |
| 0.58 | 3754 | −0.15 | 2.52 | 9.3% | 94.8% |
| 0.70 | 3378 | −5.16 | 5.21 | 12.0% | 88.2% |

（test，75 张，GT 3765 株）

如果 bias 来自标注缺失，它不会随阈值升高而消失——漏标的框本来就不在 GT 里，
模型给它们多高的置信度都改变不了"GT 少一个"这个事实。bias 能一路降到 0，
说明多出来的那些框**本来就是模型自己低置信度的猜测**。

**② 多余框有 92% 落在离任何 GT 都很远的地方。**

conf=0.25 时共 540 个 FP，拆成两类：

| 类型 | 数量 | 占 FP | 置信度中位 | 面积中位 |
|---|---|---|---|---|
| 匹配上的（TP） | 3643 | — | 0.805 | 12 157 px² |
| **紧贴 GT**（中心距 ≤ 0.5 对角线） | 42 | 7.8% | 0.445 | 4 814 px² |
| **远离所有 GT** | **498** | **92.2%** | 0.495 | **4 932 px²** |

假设 B 要求"多余框紧贴 GT"——实际只有 7.8%。而 92% 的 FP 根本不在任何植株附近。

**③ 多余框的面积只有正确框的 41%。** 12 157 → 4 932 px²。这说明模型检的不是
"另一株"，而是**同一株的局部**：密集甘蓝的叶片轮廓很像一株幼苗，模型在叶片
边缘反复出框。这类框置信度中位 0.495——不高不低，正好全落在 0.25 的保留区里。
这也解释了为什么提高阈值有效：把 0.5 以下切掉，切掉的正是这些残片。

**④ bias 与密度无关**（稀疏 +6.53 / 中等 +5.32 / 密集 +5.37）。假设 B 的常见
成因是密集区标不过来，如果成立，bias 应该随密度显著上升。没有。

## 4. 在 val 上选点，到 test 上验证

第一版是在 test 上扫的，那等于用测试集做模型选择——属于信息泄漏，所以补了一遍
val（38 张）独立扫描：

| conf | val bias | val MAE | test bias | test MAE |
|---|---|---|---|---|
| 0.25 | +4.61 | 5.76 | +5.57 | 5.71 |
| 0.52 | +0.05 | 3.21 | +1.08 | 2.71 |
| **0.55** | **−0.45** | **3.18** | **+0.49** | **2.55** |
| 0.60 | −1.74 | 3.11 | −0.61 | 2.67 |

两个集独立给出的零点都落在 **0.52~0.60**，val 是 0.52~0.55、test 是 0.55~0.58。
曲线形状一致，说明这个工作点是数据本身的性质，不是测试集的偶然。

## 5. 结论与改动

**假设 A 成立**：不是标注错，是 `conf=0.25` 这个默认值太低，把"叶片局部"的框
也放了进来。

`DEFAULT_CONF` 从 0.25 改为 **0.55**（test 上的效果）：

| | 0.25 | 0.55 | 变化 |
|---|---|---|---|
| bias | +5.57 | +0.49 | 基本无偏 |
| MAE | 5.71 | **2.55** | **−55%** |
| MAPE | 11.76% | **5.18%** | −56% |
| 完全数对 | 9.3% | 14.7% | +58% |
| Recall | 96.8% | 95.3% | −1.5pp |

代价是漏检从 122 增加到 179（75 张合计）。这是一个真实的取舍，不是纯赚：
**抬高阈值把"多报"换成了少量"漏报"**。在苗木计数场景里这两个错误方向都有成本
——多报会让人以为不用补苗，漏报会让人补多了。选 bias≈0 是因为它至少不偏。

**副作用检查**：密度分级用的是 GT 四分位（45/53/65），本来就该配无偏预测，所以
这次修正让分级**更准**而不是更偏——原来预测系统性高 5.6 株，等于把一批 medium
推成 dense。

## 6. 顺带修掉的一个真 bug

改值的时候才发现：`DEFAULT_CONF` 定义了，但**只被 1 处引用**，其余 7 处各自
硬编码 `0.25`（`cli.py`、`pipeline.py` ×3、`spec.py` ×4、`engine.py`、`mock.py`）。
所以改 config 根本不生效——第一版实验就踩到了：`CVAGENT_CONF=0.55` 跑完评测，
结果和 0.25 一模一样，还差点被当成"阈值无影响"的证据。

配置项形同虚设比没有配置项更危险：它让人觉得改过了。现在全部收敛到
`DEFAULT_CONF` 单一来源，回退仍是 `CVAGENT_CONF=0.25`。

两个测试也因此失败过，因为它们把 `0.25` 和具体株数 `48` 写死在断言里。已改成
引用 `DEFAULT_CONF`、以及"答案里的数字必须能在观测里找到"——后者才是那两条测试
真正要守的东西。

## 7. 局限

1. **只在 `base_v2_repro` 这一个权重上验证。** 换权重（注意力模块、MixUp 变体）
   最优点可能移动；语义上应该重扫一遍，而不是照抄 0.55。
2. **0.55 是在 38 张 val 上选的**，样本小，零点位置有 ±0.03 的不确定性。
   用 0.55 还是 0.58 差别不大（MAE 2.55 vs 2.52）。
3. **没有动 NMS IoU。** 那些叶片残片按理也在 NMS 的射程内，调 `iou` 可能进一步
   减少 FP。本次只改了一个变量。
4. **根因没修，只是绕开。** 模型倾向于在叶片上出框，本质是训练数据或损失的问题。
   抬阈值是最省事的一刀，不是根治。真正的修法是查训练集里有没有把叶片标成株的
   样本——这件事没做。
