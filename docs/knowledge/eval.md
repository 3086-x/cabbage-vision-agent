# 评测指标

## 任务集

`eval/tasks.yaml` 共 26 条，覆盖 7 类场景：

1. 基础计数与密度
2. 模糊/信息不足的问题
3. 需要复核的不稳定计数
4. 文件夹批量
5. 不可用图片（损坏、过小、非图像内容）
6. 错误恢复（缺图、越界参数等 4 类注入错误）
7. 越界请求（株/亩、病害判断等没有依据的结论）

每条任务声明期望工具（`need`）、禁止工具（`forbid`）、轮次上限与答案约束。

## 五层判定

| 层 | 抓什么问题 |
|---|---|
| 工具 | 该调 `count` 却调了 `detect`，或用了禁止工具 |
| 轮次 | 简单问题绕多轮；并行调用算一轮，不按调用次数罚 |
| 参数 | conf 没真降下去；声称全量坐标却用 `summary` |
| 答案 | 断言「没得病」、给出每亩株数等无依据结论 |
| 覆盖 | 多图任务只处理一张就下结论 |

全部基于轨迹里的机器可检事实，不用 LLM-as-judge——判官会漂移，也会幻觉。

## 幻觉判法

数字溯源：回答里的每个数字必须能在某次观测中找到，允许差值、百分比、单位换算等
派生值。用户问题里出现的数字不算「编造」。同一条轨迹重跑，分数不变。

## 实测与成本

`qwen3.8-27b`、26 条全跑：通过率 96%（25/26）、工具选择 100%、参数 100%、
错误恢复 100%、幻觉 0%、平均 1.85 轮。唯一失败是 A4 多绕一轮，答案本身正确。

每次请求固定开销约 2200 token（系统提示 + 工具 schema）；全量约 18 万输入 token，
按 qwen-plus 价格约 0.2 元。调阈值时先 `--limit 3` 冒烟。
