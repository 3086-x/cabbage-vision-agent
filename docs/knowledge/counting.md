# 计数口径

## 一次计数在算什么

`detect_cabbage` / `count_cabbage` 返回的 `count` 是「在给定 conf 下通过 NMS 的框数」，
不是人工点数的真值。默认 `conf=0.25`、`iou=0.45`，两者都是显式参数，不是隐藏在代码里的常量。

因此同一个数字必须连同 `conf_threshold`、`iou_threshold`、`model` 一起引用；
只报一个株数而不报阈值，等于报了一个无法复核的数。

## 阈值与复核

`refine_detection` 把 conf 从 0.25 降到 0.15，在同一次推理结果上重新过滤，
返回 before/after 两个计数与差值 `delta`。稳定性判定按**相对变化**：

- `stable`：`|delta| / before ≤ 5%`
- `unstable`：`|delta| / before > 5%`
- `no_baseline`：before 为 0（无法计算相对变化）

结论应取复核后的计数，并说明「在 conf=0.25 检出 N 株，降到 0.15 后为 M 株」。
低置信框数量 `conf_stats.n_low`（置信度 < 0.5 的框数）是是否需要复核的信号，
但它不是复核本身。

## 数字溯源

回答里的每个数字都应当能指回某次工具观测：株数指回 `count`，阈值指回调用参数，
差值和百分比属于允许的派生值。评测里的「幻觉率」就是按这条规则判的——
找不到出处的数字判为编造，而不是靠人感觉「像不像」。

## 缓存与阈值的语义

同一张图重复检测会命中进程内缓存。命中后**必须按本次 conf 重新过滤框**：
曾经用 0.15 跑过，再问 0.25 时不能直接返回 0.15 的 50 株，而要给出 49 株。
这个缺陷真实存在过，由 `tests/test_engine.py::TestCacheThresholdSemantics` 锁住。

缓存是进程内的，不跨进程；多用户部署时要换成带过期时间的外部缓存。
