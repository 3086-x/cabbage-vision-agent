# 项目局限

## 单类单场景

只识别甘蓝（单类检测），只在一种航高、一种光照条件下验证过。
换品种、换航高、换田间背景需要重新标注与重训，不能直接迁移。

## 只测了一个模型

任务集上的 96% 通过率是 `qwen3.8-27b` 一次运行的快照。温度固定为 0，
但云端推理不保证逐字复现；换 `qwen3.8-flash` 等模型分数会不同。
要把它当结论，需要多模型 × 多次运行的矩阵，这还没做。

mock provider 的 42% 不是模型能力：它按脚本行动、不读问题，只用于反向验证
判定没有过松。

## 任务集是自拟的

26 条任务覆盖 7 类场景（基础/模糊/复核/批量/不可用图/错误恢复/越界），
但问题写法由作者设计，不代表真实用户分布。它衡量「这些行为对不对」，
不衡量「用户满不满意」。

## 检测本身的边界

- 原始标注是中心点，框由估算直径扩出，mAP 绝对值不宜与其他工作横比；
  配置间的相对比较成立，因为 33 个 run 共用同一份标签。
- 注意力模块（SE/CBAM/CA）在三种子下均无可分辨增益，所以固定基线结构，
  复杂度全部投入编排层。
- 密集场景下低置信框多，单次计数可能偏低，需要复核而不是直接下结论。

## 服务与部署边界

ONNX Runtime 服务只覆盖「单图/批量前向 + 计数 + 分级」，不含 Agent 循环；
`refine_detection` 依赖进程内缓存，跨进程不可用。Docker 未做构建验证，
权重与数据集不随仓库分发。
