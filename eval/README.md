# 评测：模型会不会用这些工具

`tests/` 证明工具写对了，这里证明模型会用。两件事必须分开测——混在一起时，
模型答错你无法判断是工具描述有歧义，还是模型本身不行。

## 为什么不用现成的 agent 评测框架

试过的方案都不合适，理由是具体的：

| 方案 | 不用的原因 |
|---|---|
| RAGAS / 通用 LLM 评测 | 衡量的是文字质量，不看工具调用序列，而这里要测的恰好是"调了哪个工具" |
| 纯 LLM-as-judge | 每次跑分数都在漂，无法复现；而且判官本身也会幻觉 |
| 只测最终答案 | 答案对但过程错（比如只看了一张图就下结论）会被判为通过 |

所以判定全部基于**轨迹的机器可检事实**：调用了哪些工具、参数是什么、
回答里的数字能否在任何一次观测里找到。没有一处依赖另一个 LLM 打分。

## 四层判定

一条任务必须四层全过才算通过。少任何一层都会出现"看起来答对了"的假阳性：

| 层 | 字段 | 抓什么问题 |
|---|---|---|
| 工具 | `need` / `forbid` | 该调 `count` 却调了 `detect`；判断模糊度却跑了检测 |
| 步数 | `min_calls` / `max_calls` | 简单问题调 5 次；两张图只调 1 次 |
| 参数 | `arg_checks` | conf 没真降下去；`detail` 没设 full 却声称给了全部坐标 |
| 答案 | `match` / `not_match` / 数字溯源 | 断言"没得病"；给出每亩株数；数字在观测里找不到 |
| 覆盖 | `paths` | 多图任务只处理了一张就下结论 |

`paths` 这条是刻意加的。C3 问"两张图哪张更密"，模型只检测第一张、拿它的
数字作答，前面四层全都会通过——只有比对参数里的真实路径才能发现。

## 幻觉率怎么算

不靠判官，靠溯源。规则：回答里每个数字都必须能被某次观测里的数字解释。

三个放宽条件，目的是不冤枉合理推理：

1. **0~3 的整数豁免**——"两张图""差 2 株"这类是结构用法，不是断言
2. **允许派生值**——任意两个观测数字的差、比值的百分数，覆盖"差 +1""降了 2%"
3. **容差**——绝对 0.005、相对 0.5%，处理浮点格式化

剩下的就是编造。指标定义：

```
幻觉率 = 含无法溯源数字的任务数 / 回答中含数字的任务数
```

分母排除"回答里一个数字都没有"的任务，否则拒答类任务会被算成满分。

## 用法

```bash
# 自检：不需要 key，验证评测管线本身
python eval/run_eval.py --provider mock

# 真实模型
CVAGENT_EVAL_DATA=/path/to/test/images \
  python eval/run_eval.py --provider dashscope

# 只跑错误恢复那组，迭代 hint 文案时用
python eval/run_eval.py --provider dashscope --only recover
```

参数：`--only <分类>`、`--limit N`、`--max-steps`、`--device`、`--out-dir`。
结果写到 `eval_reports/eval_<provider>[_<分类>].{json,md}`。

## 数据与 fixture

真实图片不随仓库分发，`--data-root` 指向本地测试集（默认
`../cabbage_project/dataset/test/images`）。缺数据的任务标 **SKIP** 而不是判失败——
否则在没有数据集的环境里分数会虚假地变低。

错误恢复、不可用图这两组用的是**合成 fixture**（8×8 图、纯黑图、后缀撒谎的文本、
不存在的路径），所以这 9 条在任何机器上都能跑。

## 读分数时注意

`provider=mock` 的分数**不代表模型能力**。mock 是一个按预设脚本行动的替身
（检测 → 看 n_low → 复核 → 收束），它根本不读问题。跑它有两个用处：

1. 验证评测管线本身（能跑完、能算分、能出报告）
2. **反向验证判定没有过松**——如果 mock 在所有任务上都通过，说明约束写虚了

当前 mock 通过 35%，失败集中在工具选择（省时类、批量类）、参数（detail/conf）
和越界拒答——这三类恰好是 mock 的脚本策略无法覆盖的，符合预期。
